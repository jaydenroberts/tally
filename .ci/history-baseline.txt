# History-sweep baseline
#
# Consumed by `ci/scanner.sh --history` (see .github/workflows/history-sweep.yml).
# Each 40-hex blob OID below is reported as ACCEPTED rather than as a finding.
# Anything not listed fails the sweep.
#
# WHY THIS EXISTS. This repository was public before it had a scan gate, and its
# history contains matches that were reviewed and accepted: some are pattern
# false positives, and some are content that is already published and cannot be
# withdrawn without rewriting history, which was considered and rejected as more
# damaging than the residual. Without a baseline the sweep would be red on every
# run forever, and a check that is always red is a check nobody reads. That is a
# worse outcome than not running the sweep at all.
#
# WHAT THIS IS NOT. It is not a way to silence a finding. Every entry is pinned by
# object id, and an object id IS its content, so a line can only ever accept one
# exact byte sequence that already exists — it cannot whitelist anything future.
# Adding a line is a reviewable diff that the pull-request gate itself scans.
#
# The baseline applies ONLY to `--history`. It has no effect on `--tree`, which is
# what gates publishing, so a baselined blob still blocks a release if it is
# present in the tree being published. Verified, not assumed.
#
# If the sweep goes red: fix the finding at its source. Do not add its OID here to
# make the build green. Rationale for each acceptance is recorded outside this
# repository; this file deliberately carries object ids and nothing else.
